# 04 — واجهة الحضور

## هدف المرحلة

إنشاء واجهة عربية RTL وهاتف أولًا على `/attendance` تفصل العرض عن الإدارة،
وتقرأ وتكتب أقل قدر لازم من البيانات ضمن المدرسة والفرع والحلقة، مع بقاء RLS
المرجع النهائي.

## نقطة البداية

- المستودع: `Hassandz-bit/quran-school-platform`.
- Base branch: `main`.
- Base SHA: `efe6cd55b12cc2c7c172a27d0acee5e6669866cb`.
- الفرع: `agent/attendance-interface`.
- Migration 013 مطبقة باسم `20260725005235 — 013_attendance_module`.

## ما فُحص قبل التنفيذ

- مسارات React و`AuthContext` وحماية المسارات.
- أنماط الصلاحيات في الوحدة المالية.
- RLS الحالي لـ`branches`, `classes`, `students`.
- دالة `can_access_attendance_class` وسياسات جداول الحضور.
- صلاحيات الأدوار المضمنة:
  - المعلم والمشرف الأكاديمي يملكان `classes.view` و`students.view`.
  - المعلم لا يقرأ `teachers` أو`class_teachers` مباشرة.
  - دالة الحضور المحمية هي مرجع تعيين الحلقة للمعلم.

## التصميم المنفذ

### الحماية والصلاحيات

- `AttendanceRoute` يتطلب جلسة ومؤسسة مدرسية نشطة.
- طبقة البيانات تتحقق من `attendance.view` و`attendance.manage` كلًا على حدة.
- نطاق الفرع يُتحقق عبر `has_school_permission` و`has_branch_permission`.
- نطاق الحلقة يُتحقق عبر `can_access_attendance_class`.
- لا تُجلب أسماء الفروع والحلقات إلا بعد اجتياز فحص نطاق الحضور.
- لا تُجلب بيانات الطالب إلا بعد فحص الحلقة، وبالأعمدة:
  `id, first_name, last_name`.
- مستخدم العرض فقط لا يرى أزرار الحالة أو الملاحظات القابلة للتحرير أو زر
  الحفظ.
- دالة الحفظ نفسها تعيد فحص `attendance.manage` قبل أي كتابة.
- RLS وTriggers Migration 013 تتحقق مرة أخرى من المدرسة والفرع والحلقة
  والطالب وهوية المستخدم.

### وظائف الصفحة

- اختيار التاريخ والفرع والحلقة ضمن النطاق.
- تحميل الطلاب النشطين من الحلقة المحددة فقط.
- الحالات الأربع: حاضر، غائب، متأخر، غياب مبرر.
- وقت الوصول عند التأخر وملاحظة حتى 500 حرف.
- تعيين الجميع حاضرًا ثم تعديل الحالات الفردية.
- ملخص فوري للحالات الأربع.
- تحميل الجلسة والسجلات السابقة للتاريخ والحلقة نفسيهما.
- إنشاء الجلسة عند أول حفظ، مع استرداد آمن من تعارض التفرد `23505`.
- إدخال جماعي للسجلات الجديدة وتحديثات محددة الأعمدة للسجلات الموجودة.
- منع حفظ قائمة ناقصة أو مكررة، وإعادة التحقق من الطلاب النشطين قبل الكتابة.
- لا حذف مباشر.

### الحالات المرئية

- تحميل الصلاحيات.
- خطأ الصلاحيات أو البيانات مع إعادة المحاولة.
- عدم وجود صلاحية.
- عدم وجود فروع.
- عدم وجود حلقات.
- عدم وجود طلاب.
- وضع العرض فقط.
- جلسة جديدة أو جلسة سابقة.
- نجاح الحفظ.
- تغييرات غير محفوظة أو سجل محفوظ.
