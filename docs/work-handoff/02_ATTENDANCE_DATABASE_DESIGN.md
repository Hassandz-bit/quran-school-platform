# 02 — تصميم قاعدة بيانات الحضور

## هدف المرحلة

تصميم حضور يومي قابل للتعديل والتدقيق، مع عزل المدرسة والفرع والحلقة، وبناء
التصميم على الجداول والقيود الفعلية الموجودة.

## التصميم

### `attendance_sessions`

| العمود | النوع | الغرض |
| --- | --- | --- |
| `id` | `uuid` | معرف الجلسة |
| `school_id` | `uuid` | حد المدرسة |
| `branch_id` | `uuid` | حد الفرع |
| `class_id` | `uuid` | الحلقة |
| `session_date` | `date` | تاريخ الحضور |
| `created_by` | `uuid` | من أنشأ الجلسة |
| `created_at`, `updated_at` | `timestamptz` | التتبع |

- يمنع `unique (class_id, session_date)` تكرار جلسة الحلقة في اليوم نفسه.
- FK مركب إلى `classes(school_id, branch_id, id)` يمنع الربط العابر للنطاق.
- الجلسة غير قابلة للتعديل أو الحذف من المتصفح بعد إنشائها حتى يبقى تاريخ
  سجل التدقيق ثابت المعنى.

### `attendance_records`

| العمود | الغرض |
| --- | --- |
| `session_id`, `student_id` | الجلسة والطالب |
| `school_id`, `branch_id`, `class_id` | نسخة نطاق ثابتة للـRLS والتقارير |
| `status` | `present`, `absent`, `late`, `excused_absence` |
| `arrival_time` | اختياري للحاضر أو المتأخر |
| `note` | ملاحظة من 1 إلى 500 حرف عند وجودها |
| `recorded_by` | منشئ السجل |
| `last_modified_by` | آخر معدل |
| timestamps | التتبع |

- يمنع `unique (session_id, student_id)` التكرار.
- Trigger محمي يستخرج نطاق المدرسة والفرع والحلقة من الجلسة.
- عند الإنشاء فقط، يتحقق Trigger أن الطالب نشط وفي الحلقة نفسها.
- هوية الجلسة والطالب والنطاق و`recorded_by` غير قابلة للتعديل.
- يسمح ذلك بنقل الطالب لاحقًا دون كسر تاريخ حضوره السابق.

### `attendance_record_history`

- سجل append-only لكل إنشاء أو تعديل فعلي.
- يحتفظ بالحالة والوقت والملاحظة القديمة والجديدة، ومن أحدث التغيير ووقته.
- لا توجد منح متصفح للإضافة أو التعديل أو الحذف.
- Trigger `security definer` هو الكاتب الوحيد.

## الصلاحيات

- `attendance.view`.
- `attendance.manage`.
- لا يوجد بديل حالي يؤدي المعنى نفسه.
- تُمنح افتراضيًا إلى:
  - `school_admin`
  - `branch_manager`
  - `academic_supervisor`
  - `teacher`

## نموذج RLS

- غير المعلم:
  - الدور المدرسي يرى المدرسة كلها.
  - الدور الفرعي يرى فرعه فقط.
- دور `teacher`:
  - يحتاج صلاحية الحضور.
  - يحتاج `teachers.profile_id = auth.uid()`.
  - يحتاج تعيينًا نشطًا للحلقة في `class_teachers`.
- كل سياسات القراءة تقبل `attendance.view` أو `attendance.manage`.
- كل سياسات الإنشاء والتعديل تتطلب `attendance.manage`.
- لا توجد سياسة حذف.
- `anon` لا يملك جداول أو تنفيذ دالة التفويض.

## الفهارس والقيود

- الجلسات حسب المدرسة والفرع والتاريخ.
- الجلسات حسب المدرسة والحلقة والتاريخ.
- السجلات حسب الجلسة والحالة.
- السجلات حسب المدرسة والحلقة والطالب.
- التاريخ حسب سجل الحضور ووقت التغيير.
- التاريخ حسب المدرسة والحلقة ووقت التغيير.

## القرارات وأسبابها

- لم تُستخدم FK تربط `student.class_id` بتاريخ الحضور؛ لأنها كانت ستمنع نقل
  الطالب بين الحلقات بعد وجود حضور تاريخي.
- استُخدم تحقق server-side عند إنشاء السجل بدلًا منها.
- لم يُضف حذف منطقي لسجل الحضور؛ الحالة الحالية تُعدل، والتاريخ يحفظ كل تغيير.
- لم تُضف حالات إغلاق الجلسة أو نظام تجويد أو تعرف صوتي لأنها خارج المرحلة.
