## Issue #29 — عطل وضع نموذج الحفظ

أثناء الاختبار التشغيلي أُنشئ سجل حفظ بنجاح، ثم أعادت الواجهة النموذج تلقائيًا إلى وضع إنشاء سجل جديد. عند تعديل القيم والضغط على الحفظ أُنشئ سجل ثانٍ بدل UPDATE للسجل الأول.

### السبب الجذري

بعد نجاح `saveMemorizationRecord` كان `handleSave` يستدعي:

```ts
setDraft(createMemorizationDraft(recordDate, defaultTeacherId));
```

وبذلك كان `recordId` يُمسح فورًا، فيسلك الحفظ التالي مسار INSERT.

### الإصلاح

- الاحتفاظ بـ`result.recordId` بعد الإنشاء والتحديث.
- إبقاء النموذج في وضع `تعديل سجل المتابعة` بعد الحفظ.
- إبقاء زر الحفظ باسم `حفظ التعديل`.
- الاحتفاظ بالقيم المحفوظة مع تنظيف المسافات في `notes` و`nextAssignment`.
- إضافة شارة `وضع التعديل` ومعرف مختصر للسجل.
- إضافة تنبيه ثابت بأن الحفظ التالي سيعدّل السجل الحالي.
- بدء سجل آخر فقط من زر `سجل جديد` داخل سياق النموذج الحالي.
- لا تغيير في طبقة قاعدة البيانات أو Migration 014.
